📖 项目概述

红石逻辑解谜 是一个基于 Minecraft 红石电路 逻辑的 交互式解谜游戏 和 关卡设计工具。 玩家需要在网格上摆放红石元件（红石粉、中继器、比较器、火把等）， 将输入信号以正确的 延迟、持续时间 和 信号强度 传递到输出端。 项目同时提供了 可视化关卡编辑器（Python/Tkinter）， 可自由设计关卡并导出为 JSON 格式，再通过生成器编译为可独立运行的 HTML 游戏。

✨ 功能

🎮 游戏功能

  • 19+ 内置关卡：从基础红石粉连线到逻辑门（与门、或门、非门），难度循序渐进。
  • 实时信号模拟：120ms/tick 的离散时间步进，精确模拟红石信号传播、衰减、中继器延迟、比较器运算、活塞推拉。
  • 信号可视化：红石粉上显示信号强度（1–15），信号流动动画，输出点状态指示。
  • 播放/暂停/单步：可控制模拟速度，逐 tick 调试电路。
  • 元件限制：每个关卡可设置每种元件的最大使用数量，增加策略性。
  • 存档/读档：保存当前进度和电路布局，支持 JSON 存档文件导入导出。
  • 自由模式：20×12 大画布，开放所有元件，无对错限制，自由搭建电路。
  • 元件教程：首次解锁新元件时弹出介绍弹窗，包含用途说明和操作提示。

🛠️ 关卡编辑器 (do_game.py)

  • 可视化设计：Tkinter 图形界面，拖拽放置元件，设置输入/输出点。
  • 元件限制管理：为每种元件设置数量上限，禁用不使用的元件。
  • 多输入支持：支持 2 个以上输入点，可独立配置延迟偏移、持续时间和强度。
  • 目标参数配置：设置目标延迟、持续时间和可选的信号强度。
  • 即时仿真：在编辑器中即可运行模拟，验证关卡是否可解。
  • 导入/导出 JSON：关卡数据保存为 JSON 格式，便于版本管理和分享。

🌐 联机功能

  • P2P 连接：基于 simple-peer 库的 WebRTC 点对点连接，无需服务器。
  • 分区域协作：玩家1（主机）负责左半区，玩家2（加入方）负责右半区。
  • 实时同步：元件放置/移除/修改、模拟控制、关卡切换等操作实时同步。
  • 聊天系统：文字聊天 + 语音消息（浏览器录音），增强协作体验。
  • 队友光标：显示队友的鼠标位置，便于沟通。

🎮 玩法

  1. 选择关卡：从顶部关卡栏选择关卡（1–19+），或从主页进入。
  2. 理解目标：信息栏显示目标延迟、持续时间和可选信号强度。
  3. 选择元件：从右侧元件栏选择可用元件，受限元件会显示剩余数量。
  4. 放置元件：左键点击网格放置当前选中的元件，右键移除元件。
  5. 调整方向：按 R 键旋转元件方向（中继器/比较器/火把等有方向性）。
  6. 修改参数：点击已放置的中继器可调整延迟档位（1–4），点击比较器切换比较/减法模式。
  7. 运行模拟：点击「播放」按钮运行电路，观察信号传播，点击「单步」逐 tick 调试。
  8. 过关条件：当输出信号的延迟、持续时间和强度（若有）全部匹配目标值时，即过关。

💡 提示：信号强度会随红石粉距离衰减（每格 -1），使用中继器可恢复强度至 15。 中继器延迟档位 = 1–4 tick，实际延迟 = 档位 + 1 tick。

📁 关卡定义格式

关卡数据以 JSON 格式定义，支持单输入和多输入两种模式。

完整字段说明

字段类型必填说明
namestring✅关卡名称
descstring✅关卡描述（显示在信息栏）
cols / rowsint✅网格列数/行数
inputobject⭕单输入：{x, y, duration, strength}
inputsarray⭕多输入：[{x, y, duration, strength, delay}]
outputobject✅输出点：{x, y}
targetobject✅目标：{delay, duration, strength?}
componentsarray✅可用元件列表
limitsobject⭕元件数量限制：{ "repeater": 3 }
hintstring✅通关提示
parint⭕推荐元件数（用于星级评价）
logicstring⭕逻辑门类型：not or and
preplacedarray⭕预放置元件（玩家不可移除）

示例：单输入关卡

{ "name": "初识红石", "desc": "用红石粉连接输入和输出", "cols": 8, "rows": 6, "input": {"x": 1, "y": 3, "duration": 10, "strength": 15}, "output": {"x": 6, "y": 3}, "target": {"delay": 4, "duration": 10}, "components": ["dust"], "limits": {}, "hint": "选中红石粉，点击网格放置", "par": 5, "preplaced": [] }

示例：多输入关卡（或门）

{ "name": "逻辑或门", "desc": "两路信号汇合，任一输入有信号时输出就有信号", "cols": 12, "rows": 8, "inputs": [ {"x": 1, "y": 2, "duration": 10, "strength": 15, "delay": 0}, {"x": 1, "y": 6, "duration": 10, "strength": 15, "delay": 5} ], "output": {"x": 10, "y": 4}, "target": {"delay": 10, "duration": 15}, "components": ["dust"], "logic": "or" }

🛠️ 工具链

1. 关卡设计器 (do_game.py)

Python + Tkinter 编写的可视化关卡编辑器。

  • 启动：python do_game.py
  • 功能：拖放元件、设置输入/输出、配置目标、运行模拟验证。
  • 输出：导出 .json 关卡定义文件。

2. 游戏生成器 (gen_redstone_game.py)

将 JSON 关卡定义编译为独立的 HTML 游戏文件。

  • 用法：python gen_redstone_game.py levels.json output.html
  • 输出：一个包含完整游戏引擎和所有关卡的 .html 文件。

3. 游戏本体 (redstone-puzzle.html)

可独立运行的 HTML 游戏，包含所有功能：

  • 纯前端（HTML + CSS + JavaScript），无需后端服务
  • 使用 Canvas 渲染电路
  • 支持 localStorage 保存进度
  • 内置 WebRTC 联机功能

🌐 联机模式

联机功能基于 WebRTC 和 simple-peer 库，实现点对点连接。

连接流程

  1. 主机（P1）：点击「创建房间」，生成邀请码（Signal 数据）。
  2. 加入方（P2）：点击「加入房间」，粘贴主机提供的邀请码。
  3. 加入方生成应答码，主机粘贴应答码完成连接。
  4. 连接建立后，双方各自负责左/右半区，操作实时同步。

协作机制

  • 区域划分：网格以中间列（Math.floor(cols/2)）为界，左侧归 P1，右侧归 P2。
  • 操作限制：玩家只能在自己的区域内放置/移除元件。
  • 同步内容：元件操作、模拟控制（播放/暂停/重置/单步）、关卡切换、光标位置。
  • 聊天：文字消息 + 语音消息（Web Audio 录音）。

⚠️ 注意：联机需要双方网络支持 WebRTC（通常需要公网 IP 或 NAT 穿透）。 如果连接失败，可尝试使用 simple-peer 的 TURN/STUN 服务器配置。

信号模拟核心

  • 离散时间步进：每 tick（120ms）更新一次所有元件状态。
  • 信号传播：红石粉从相邻信号源接收信号，强度 = max(相邻信号) - 1。
  • 方向性元件：中继器、比较器、火把、侦测器只从指定方向接收信号。
  • 中继器：延迟 = 档位 + 1 tick，输出强度固定为 15。
  • 比较器：比较模式（主输入 ≥ 侧输入 → 输出主输入），减法模式（输出 = 主输入 - 侧输入）。
  • 侦测器：检测前方信号从 0→1 的上升沿，输出 2 tick 脉冲。
  • 活塞：相邻方向有信号时伸出，推拉石头/红石块，机械延迟 2 tick。

📝 关卡设计指南

设计原则

  • 循序渐进：从简单直线连接开始，逐步引入中继器、比较器、火把等元件。
  • 目标清晰：每个关卡应有明确的"教学目的"（如：延迟、脉冲转换、信号强度、逻辑门）。
  • 可解性验证：使用编辑器中的仿真功能验证关卡是否可解。
  • 元件限制：通过 limits 字段限制元件数量，迫使玩家寻找最优解。
  • 提示信息：提供具体、可操作的提示，帮助卡关的玩家。

推荐关卡结构

{ // 基础信息 "name": "关卡名称", "desc": "简短描述", "cols": 12, "rows": 8, // 输入配置（单输入） "input": {"x": 1, "y": 4, "duration": 15, "strength": 15}, // 输出配置 "output": {"x": 10, "y": 4}, // 目标参数 "target": {"delay": 12, "duration": 10, "strength": 15}, // 可用元件及限制 "components": ["dust", "repeater"], "limits": {"repeater": 2}, // 提示 "hint": "用中继器增加延迟", // 推荐元件数（用于星级评价） "par": 10 }

逻辑门关卡设计

  • 非门 (NOT)：使用红石火把实现反相。输入有信号 → 火把熄灭 → 输出 0；输入无信号 → 火把点亮 → 输出 15。
  • 或门 (OR)：两路红石粉在同一个点汇合即可。任一输入有信号，汇合点就有信号。
  • 与门 (AND)：使用比较器（减法模式）+ 火把反相。A 接主输入，B 经火把反相后接侧输入。输出 = A - (NOT B)。

💡 提示：在关卡定义中添加 "logic": "not" / "or" / "and" 字段，游戏会在进入关卡时自动显示对应的逻辑门介绍。
